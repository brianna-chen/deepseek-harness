# Agent Note：Memory ME 可移植编程记忆中心

状态：已实现

中文 | [English](2026-08-18-memory-me.md)

## 问题

开发者在 Codex、Claude Code 与 DeepSeek Harness 之间切换时，需要携带可移植指令与 Skills，同时避免复制凭据、聊天、日志、缓存或平台专属状态。迁移过程还需要可检查的冲突、恢复能力，以及记忆确实进入 Harness 运行时的证据。

## 决策

Memory ME 0.2 完整取代原 ComeHere 原型。它是社区 scope 下的可安装 bundle，由 Host Remote 服务、Web 设置中心和 `memory_me` 模型工具组成。

Host 只发现文档明确的指令与 Skill 根目录。预览不写入，并返回来源/目标摘要、行变更、冲突动作和逐行敏感信息提示。冲突策略包括跳过、Skill 安全改名、备份后替换，以及带可选编辑内容的合并。导入与回滚都要求明确确认。每次成功写入都会验证、记录历史，并写入可执行回滚清单。Harness 记忆可导出为可移植 JSON。

浏览器目录选择只接收 `AGENTS.md`、`CLAUDE.md` 和 `SKILL.md`，拒绝任意相邻文件。大小限制、符号链接拒绝、敏感信息扫描和目标重新解析仍由 Host 持有。

## 考虑过的替代方案

**保留 ComeHere 兼容别名。** 未采用，因为功能尚未在上游正式发布，并且本次要求完整更名。

**静默覆盖冲突。** 未采用。替换与合并必须作为明确预览动作，并先创建备份。

**把生成报告当作运行时生效证明。** 未采用。确定性测试分别针对 Codex 与 Claude Code，通过 Harness 指令渲染器加载导入指令，并通过文件系统 Skill 注册表加载导入 Skill。

## 影响

npm 包族迁移到 `@brianna-chen` scope，版本为 `0.2.0`。默认 Web 组合挂载 Memory ME，生成的工具目录包含 `memory_me`。图形流程仍为来源、选择、冲突处理、确认、进度和报告，并在相应边界提供历史、导出、验证和可执行回滚。
