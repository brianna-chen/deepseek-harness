# Agent Note：ComeHere 图形化记忆导入

Status: implemented

[English](2026-08-18-come-here-memory-import.md) | 中文

## 问题

从 Codex 或 Claude Code 迁移的开发者，需要把可移植的指令和 skill 有意识地带入 DeepSeek Harness。直接复制整个平台配置目录并不安全，因为其中还可能包含凭据、日志、对话、缓存和平台专属状态。纯命令流程也无法在导入前、导入中和导入后提供充分反馈。

## 决策

ComeHere 作为一个 Settings 页面，由专用 Host Remote 服务提供能力。它支持从服务端固定目录发现内容，也支持浏览器明确上传 Markdown 文件。界面先展示指引和数据声明，再让用户选择平台、范围和具体候选项；写入前预览每一项动作并要求最终确认；执行时显示阶段进度；完成后返回逐项报告和已创建路径的回滚清单。

安全约束由 Host 负责。它只从已知目录导入指令和 skill 包，执行单文件与总大小限制，拒绝疑似敏感信息和符号链接，并且绝不覆盖 Harness 已有文件。指令冲突直接跳过；只有用户勾选时，skill 冲突才采用重命名。预览不写文件，实际导入会重新解析请求，因此预览后新出现的目标文件仍会被跳过。

## 考虑过的替代方案

**把现有 skill 做成纯文本向导。** 未采用，因为目标体验需要原生选择、进度和可留存报告。

**上传或复制完整平台目录。** 未采用，因为平台主目录混合了可移植记忆、凭据和其他隐私状态。

**确认后覆盖冲突。** 未采用，因为只创建不覆盖更容易审计，也能让生成的回滚清单保持真实。

## 后果

Web bundle 增加一个 Host 插件和一个客户端 Settings 插件。向导展示来源、选择、冲突处理、确认、逐项导入进度和完成报告六个节点，返回上一步时保留用户选择。每个选中项作为一次有边界的 Remote 操作执行，因此进度对应已经完成的项目；最终报告汇总精确结果与所有回滚清单。浏览器上传接收独立 Markdown 文件；包含相对资源的完整 skill 包通过服务端发现导入，以保持目录结构。

确定性运行时测试分别覆盖 Codex 和 Claude Code。每个用例导入唯一的指令与 Skill 探针，验证探针进入 Harness 指令渲染器和文件系统 Skill registry，并确认来源指令没有变化。这些测试无需依赖不稳定的模型输出即可证明运行时可见性。
